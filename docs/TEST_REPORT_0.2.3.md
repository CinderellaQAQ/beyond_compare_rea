# BC3 MultiDetails 0.2.3 发布测试记录

测试目标为 Windows BC3 3.3.5 build 15075，`BCompare.exe` SHA-256：
`1d822b3faabb8f65fc30076d32a95757a2c369ccb64ae54572e9f562280ae845`。

## 原问题复现

- 使用正式 0.2.2 DLL，在隔离 Wine/Win32 环境打开普通短文本比较。
- 第一次单击上方正文行，底部开始显示差异时稳定弹出
  `An error occurred in the application`。
- 正式 0.2.2 日志停在“开始绑定第一个底部编辑器”；在相同源码中加入逐调用
  定位日志后，确认旧数据源已脱离，而下一条“代理数据源已绑定”未出现，因此
  异常发生在 BC3 原生 `SetDataSource` 同步绑定代理期间。
- 在同一环境、同一文件和同一点击位置进行修复前后 A/B 验证；只把代理状态
  提前到绑定前发布后，该必现步骤即通过。

## 根因与修复

- BC3 的原生 `SetDataSource` 不是单纯保存指针；它会同步重建行数、滚动、
  当前行和样式缓存，并在返回前触发 `CurrentChanged` 及两条样式回调。
- 0.2.2 在所有编辑器绑定完成后才把 `proxy_active` 设为真。绑定窗口内，回调
  因而把代理局部行号当成原始比较行号，原版单行同步也可能把原始当前行写回
  一个行数更少的代理，最终触发 Delphi 原生断言。
- 0.2.2 还会在左右编辑器仍绑定同一个代理对象时原地改写其 `count/map`；较慢
  电脑、不同当前行或重绘时序下，一个编辑器可能看到新映射和旧缓存的组合。
- 0.2.3 改为两阶段重绑：先让全部底部编辑器脱离旧代理，在无人引用时一次性
  发布新 `map/count` 和活动状态，再依次绑定所有编辑器。
- 样式回调现在以编辑器实际持有的代理指针为映射依据，不再依赖稍后更新的
  活动标志。
- 当最后一条选择被 `Ctrl` 取消时，先用旧映射恢复原始行，再清空代理，避免
  丢失当前行位置。

## 回归结果

- 普通短文本：首次单击、三条 `Ctrl` 不连续选择、逐条取消直至零条均通过。
- 两个各 10,000 行的样本中，同时选择三条各 10,001 字符的差异行；左右原生
  Text Details 完整显示，无错误对话框。
- 底部横向滚动八页到位置 1,144，全部选中行同步移动。
- 点击底部第三条后，日志确认代理项目 2 映射到原始项目 8，上方正文自动跳转。
- 在底部执行 `Home`、`Shift+End`、`Ctrl+C`，剪贴板为
  `CF_UNICODETEXT 10000`，无截断。
- 使用另一套独立 Wine 用户配置冷启动，首次绑定及三条超长行选择通过。
- 150% DPI 独立配置下，首次绑定及三条超长行选择通过。
- 正式 0.2.2 安装器安装后，0.2.3 安装器原地升级成功；升级前后
  `BCompare.exe` 哈希不变。
- 干净构建无编译警告，`git diff --check` 通过。
