# BC3 MultiDetails 0.2.4 发布测试记录

测试目标为 Windows BC3 3.3.5 build 15075，`BCompare.exe` SHA-256：
`1d822b3faabb8f65fc30076d32a95757a2c369ccb64ae54572e9f562280ae845`。

## 原问题复现

- 在两个各 10,000 行的文本中，用 `Ctrl` 同时选择三条 10,000 字符差异行。
- 拖动底部唯一的横向滚动条时，正式 0.2.3 只有下半组详情内容移动，上半组
  保持在原位置。
- 自动像素回归中，下半原生详情编辑器变化 12,424 个像素，上半编辑器变化为
  0，稳定复现不同步。

## 根因与修复

- BC3 的共享横向滚动条是下半 `TUiEditor` 的子控件，`WM_HSCROLL` 发送给
  外层 `TUiEditor`；旧代码只监听内层 `TUiEditorWindow`，同步函数没有收到
  滚动条拖动和翻页消息。
- 0.2.4 同时挂接详情编辑器的外层和内层原生窗口：外层处理横向滚动同步，
  内层继续处理光标、选区、复制和键盘操作。
- BC3 原生横向位置设置器不会自动限制越界值。长行移动到末尾后恢复原始数据
  源，旧偏移可能超过新范围并触发断言。所有同步和恢复路径现在先按目标编辑器
  的最大有效横向位置限制偏移。

## 回归结果

- 修复前同步检查：上半区 0 像素、下半区 12,424 像素，测试按预期失败。
- 修复后同步检查：上半区 11,856 像素、下半区 12,424 像素，测试通过。
- 真实鼠标拖动滑块后，上下两组共六条详情内容位于相同字符位置。
- 点击底部详情行后，上方正文自动跳转到对应原始行。
- `Home`、`Shift+End`、`Ctrl+C` 后剪贴板为 `CF_UNICODETEXT 10000`。
- 修复前“滚动—选择—复制—退出”稳定出现 madExcept 异常窗口；修复后 4 秒
  内正常关闭且无异常窗口。
- 干净构建无编译警告，`git diff --check` 通过。
